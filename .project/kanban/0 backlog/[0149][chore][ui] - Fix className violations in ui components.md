# [0149][chore][ui] Fix className violations in UI components

**Severity**: Low
**Category**: Frontend / Code Quality
**Estimated Effort**: XSmall
**Risk**: Medium — shared primitives used everywhere; test build carefully
**Related**: Codebase-wide design-token enforcement (see also 0147, 0148)

---

## Context

The project forbids arbitrary Tailwind values and raw color palette classes. This ticket cleans up
violations in `src/frontend/components/` — the shared UI primitive layer.

> ⚠️ **HIGH CARE REQUIRED**: Many files in `components/ui/` are generated by shadcn/ui (e.g.,
> `dialog.tsx`, `calendar.tsx`, `switch.tsx`, `select.tsx`). Arbitrary values in those files may
> be intentional sizing from the shadcn component spec. **Only modify the files explicitly listed
> below.** Do NOT touch any other file in `components/ui/` unless listed here.

---

## Token Mapping Reference

| Raw class(es) | Replace with |
|---|---|
| `text-[10px]` | `text-2xs` |
| `text-green-600 dark:text-green-400` | `text-positive` |
| `text-red-600 dark:text-red-400` | `text-negative` |
| `text-amber-600 dark:text-amber-400` | `text-accent-gold` |
| `text-blue-600 dark:text-blue-400` | `text-primary` |
| `text-gray-600 dark:text-gray-400` | `text-muted-foreground` |
| `bg-green-50 dark:bg-green-950` | `bg-positive/5` |
| `border-green-200 dark:border-green-800` | `border-positive/20` |
| `bg-red-50 dark:bg-red-950` | `bg-negative/5` |
| `border-red-200 dark:border-red-800` | `border-negative/20` |
| `bg-blue-100 text-blue-800 dark:bg-blue-900/30 dark:text-blue-500` | `bg-primary/10 text-primary` |

### ⚠️ DO NOT replace these

- `text-[0.8rem]` in `calendar.tsx` — shadcn-generated file, leave entirely untouched.
- `bg-gradient-to-r from-zinc-800 to-zinc-950` in `button.tsx` (the `"dark-solid"` variant) — intentional dark button gradient, no token equivalent.
- `border-amber-500/30 text-amber-600 dark:text-amber-400 hover:bg-amber-500/10` in `button.tsx` (warning outline variant) — this is the design-system button variant; it intentionally uses amber. Leave as-is.
- `bg-[var(--positive-bg)] text-[var(--positive)]` in `badge.tsx` — these use the correct CSS variable syntax and are fine.
- `bg-[var(--negative-bg)] text-[var(--negative)]` in `badge.tsx` — same, leave as-is.
