# Feature Enhancement: Manual Sell Holding (Historical Transaction Based)

## Objective

Enhance the selling process of a holding to follow a proper financial transaction model:

- Selling must create a historical SELL transaction
- Holding must not be deleted or overwritten
- Market price must not affect SOLD holding
- SOLD holding must display realized result instead of estimated value
- Support bulk sell from simulation feature

This feature must preserve auditability, historical accuracy, and financial consistency.

---

# Business Rules

## Core Principles

1. 1 Holding = 1 Target
2. 1 Holding = 1 Quantity (no partial sell)
3. Sell is a historical event
4. Holding data must be immutable (except status)
5. Market price is only used for ACTIVE holdings

---

# Data Model Requirements

## Holding Table

Fields:
- id
- target_id
- asset_id
- buy_price
- buy_date
- status (ACTIVE | SOLD)
- sold_transaction_id (nullable)
- created_at
- updated_at

Notes:
- Do NOT delete holding when sold
- Do NOT modify buy_price or buy_date after sell
- Only update:
  - status
  - sold_transaction_id

---

## Transaction Table

Fields:
- id
- holding_id
- type (BUY | SELL)
- price
- transaction_date
- notes (optional)
- created_at

Rules:
- SELL must create a new transaction row
- SELL transaction must be immutable
- SELL price is user input (not market-driven)

---

# Sell Flow (Bulk from Simulation)

## Step 1 — User Selects Holdings
From simulation buyback page:
- User selects multiple holdings via checkbox
- Click "Sell Selected"

## Step 2 — Sell Modal

Input Fields:
- Sell price (required)
- Transaction date (required, default = today)
- Notes (optional)

No quantity input required.

---

## Step 3 — Confirmation Preview

Before confirm, show:

- Buy price
- Sell price (input)
- Realized profit / loss
- Target name
- Sell date

User must confirm explicitly.

---

## Step 4 — System Process (For Each Holding)

1. Insert SELL transaction
2. Update holding:
   - status = SOLD
   - sold_transaction_id = transaction.id

Must be executed in a database transaction (atomic).

# UI/UX Requirements

## Holding List View

### ACTIVE Holding

Display:
- Asset name
- Target name
- Buy price
- Current market price
- Estimated value
- Unrealized P/L
- Status badge: ACTIVE

---

### SOLD Holding

Remove:
- Current market price
- Estimated value
- Unrealized P/L

Replace with:
- Buy price
- Sold price
- Sold date
- Realized P/L
- Status badge: SOLD

Sold price = value from SELL transaction (user input).

Visual:
- Slightly muted styling
- Clear SOLD badge

---

## Holding Detail Page

### ACTIVE State

Sections:
- Investment Info
- Current Valuation
- Sell Button

---

### SOLD State

Sections:
- Investment Info (Buy data)
- Sell Info:
  - Sell price
  - Sell date
  - Realized P/L
- Performance Summary:
  - Total Profit
  - Return %
  - Holding Duration

No sell action available.

---

# Calculation Rules

Realized P/L:

realized_profit = sell_price - buy_price

Return %:

return_percentage = (sell_price - buy_price) / buy_price * 100

Holding duration:

sell_date - buy_date

---

# Important Constraints

- Market price must NOT affect SOLD holding
- SELL transaction must be immutable
- Cannot sell holding if status = SOLD
- Bulk sell must process each holding independently but atomically

---

# Edge Case Handling

- Reject sell if holding already SOLD
- Reject sell if sell price <= 0
- Prevent duplicate sell submission
- All operations must use DB transaction
